# SentinelOps Dual-Stack Architecture Design

**Date:** 2026-03-16
**Status:** Approved
**Author:** Collaborative design session

---

## Overview

SentinelOps evolves from a single Rust service into a dual-stack platform with:

1. **sentinelops-agent** (new Rust crate) — OS-level event capture, gRPC client
2. **sentinelops-rust** (existing, evolved) — Aggregator/Edge Node, L1 detection, ML features
3. **sentinelops-control** (new Java 21) — Control Plane orchestrator, high throughput

Communication between Rust and Java uses **gRPC over mTLS** (Zero Trust).

## 1. Repository Structure

The existing repo at `sentinelops/` becomes a **Cargo Workspace** using the hybrid
`[workspace] + [package]` pattern in the root `Cargo.toml`. No files are moved.

```toml
# Cargo.toml (root) — hybrid workspace + package manifest
[workspace]
members  = [".", "sentinelops-agent"]
resolver = "2"

[package]
name    = "sentinelops-rust"
version = "0.2.0"
edition = "2021"
# ... existing [dependencies] unchanged
```

This is the zero-disruption path: all existing `cargo` invocations, the sqlx offline
cache (`.sqlx/`), and CI scripts continue to work. The agent is a separate crate at
`sentinelops-agent/` with its own `Cargo.toml` and `build.rs`.


## 1a. Pre-condition: Database Schema Fix (blocker)

**Problem:** The init migration (`20260307_init.sql`) created column `metadata JSONB NOT NULL`.
The later migration (`20260315141630_add_meta_to_events.sql`) added a **second, separate**
column `meta JSONB` (nullable) instead of renaming the original. The `Event` model maps to
`meta`, but all historical data lives in `metadata`. `SELECT * FROM events` returns both
columns; sqlx `FromRow` maps `meta` (always null for old rows) and ignores `metadata`.

**Fix:** A new migration must be applied **before any implementation work begins**:

```sql
-- migrations/20260316_fix_meta_column.sql
-- Step 1: migrate existing data from metadata → meta
UPDATE events SET meta = metadata WHERE meta IS NULL;

-- Step 2: enforce NOT NULL and default now that data is migrated
ALTER TABLE events ALTER COLUMN meta SET NOT NULL;
ALTER TABLE events ALTER COLUMN meta SET DEFAULT '{}';

-- Step 3: drop the now-redundant original column
ALTER TABLE events DROP COLUMN metadata;
```

This migration is idempotent-safe if applied on a fresh DB (no rows → UPDATE is a no-op).
After this migration, the schema has exactly one JSONB column on `events`: `meta`.

## 2. Protocol: gRPC over mTLS

**Choice rationale:**
- gRPC runs over HTTP/2: connection multiplexing, single TCP connection for thousands of events
- Protobuf: binary serialization, ~5–10× smaller payload than JSON, no UTF-8 validation overhead
- Client-side streaming: agent dispatches N events without waiting for per-event ACK
- mTLS: mutual certificate authentication — passwords/API keys can leak; certificates have lifecycle control

**Why not REST:** JSON serialization CPU overhead is prohibitive at millisecond-level telemetry rates.

## 3. Protobuf Contract — `proto/sentinel.proto`

### 3.1 Service definition

```protobuf
syntax = "proto3";

package sentinel;

option java_multiple_files  = true;
option java_package         = "com.sentinelops.grpc";
option java_outer_classname = "SentinelProto";

service IngestionService {
  // Unary: single event, used for debug / critical events needing individual ACK
  rpc SendEvent (SecurityEvent) returns (EventResponse);

  // Client-side streaming: production mode
  // Agent opens ONE HTTP/2 stream, pushes N events, server responds once with StreamSummary
  rpc StreamEvents (stream SecurityEvent) returns (StreamSummary);
}

message SecurityEvent {
  string event_id        = 1;  // UUID v4, lowercase, generated by agent
  string timestamp       = 2;  // RFC 3339 UTC, e.g. "2026-03-16T12:00:00Z"
  string event_type      = 3;  // MUST use canonical taxonomy (see §3.2)
  string source_ip       = 4;  // origin IP of the event (not the agent IP)
  bytes  meta_payload    = 5;  // encoded payload — codec declared by payload_encoding
  string agent_id        = 6;  // UUID v4 lowercase, must match CN in mTLS client cert
  string source_host     = 7;  // FQDN or hostname of host OS
  uint32 payload_encoding = 8; // 0=RAW_JSON, 1=ZSTD_JSON, 2=ZSTD_MSGPACK (default: 0)
}

message EventResponse {
  bool   accepted = 1;
  string message  = 2;
  string event_id = 3;  // echo of event_id for client-side correlation
}

message StreamSummary {
  uint32 accepted_count = 1;
  uint32 rejected_count = 2;
  string session_id     = 3;  // gRPC session ID for audit trail
}
```

### 3.2 Canonical `event_type` taxonomy

All agents MUST use strings from this table. The sentinelops-rust L1 detection engine
maps these same strings in its `DetectionEngine::evaluate` match arm.

| event_type string       | Meaning                                  | L1 detection rule |
|-------------------------|------------------------------------------|-------------------|
| `auth.login.failed`     | Authentication failure                   | brute-force       |
| `network.scan`          | Network port scan activity               | port-scan         |
| `os.process.exec`       | Process execution on host OS             | (future)          |
| `net.conn.outbound`     | Outbound TCP/UDP connection              | (future)          |

**Constraint:** The existing `DetectionEngine` branches on `"auth.login.failed"` and
`"network.scan"`. Events from `sentinelops-agent` using those strings will trigger L1
detection in hybrid/autonomous mode. New `os.*` / `net.*` types will pass through
silently until detection rules are added — this is intentional.

### 3.3 `meta_payload` encoding contract

`payload_encoding` field values and their expected content:

| Value | Constant      | Content                        | Decoder                |
|-------|---------------|--------------------------------|------------------------|
| 0     | `RAW_JSON`    | UTF-8 JSON bytes (no compress) | `serde_json::from_slice` |
| 1     | `ZSTD_JSON`   | zstd-compressed UTF-8 JSON     | zstd decompress → JSON |
| 2     | `ZSTD_MSGPACK`| zstd-compressed MessagePack    | zstd → rmp-serde       |

**Initial implementation uses `RAW_JSON` (0).** `ZSTD_JSON` is the target for production
high-volume paths. Both sides must agree on the codec via this field — the receiver
MUST NOT guess.

### 3.4 Key design decisions

- `bytes meta_payload` not `string`: avoids Protobuf UTF-8 validation CPU cost; accepts binary encodings
- `StreamSummary` separate from `EventResponse`: streaming returns aggregate stats, not per-event struct
- `agent_id` must match cert CN (lowercase): enforces Zero Trust at payload level, not just transport layer
- RFC 3339 `string` timestamp: avoids `google.protobuf.Timestamp` dependency; upgrade path available

## 4. Component: sentinelops-agent (Rust)

### 4.1 Java dependency versions

The `sentinelops-control` pom.xml MUST use:

| Artifact | Version |
|----------|---------|
| Spring Boot | ≥ 3.2.0 (required for Virtual Thread support) |
| `grpc-server-spring-boot-starter` | `net.devh:grpc-server-spring-boot-starter:3.1.0.RELEASE` |
| Java | 21 |

`application.yml` must also include:
```yaml
spring:
  threads:
    virtual:
      enabled: true
```

### 4.2 AgentMode

Configured via `AGENT_MODE` env var:

| Mode | sentinelops-agent behavior | sentinelops-rust behavior |
|------|---------------------------|---------------------------|
| `autonomous` | **Does not start.** The existing `sentinelops-rust` binary runs standalone, exactly as it does today. The agent crate is not involved. | Runs standalone with HTTP API, L1 detection, DB ingest |
| `subordinate` | Runs Collector + StreamingSession. Forwards all events to Control Plane via gRPC. No local persistence. | Not started |
| `hybrid` | Runs Collector. Fans out events: one copy to gRPC stream (Control Plane), one copy to sentinelops-rust via HTTP POST or internal channel. | Runs with L1 detection + DB ingest |

**`autonomous` clarification:** in this mode, sentinelops-agent binary is not deployed.
The existing sentinelops-rust service is the complete system. This mode describes the
current production state and requires no changes to sentinelops-rust.

### 4.3 StreamingSession

Core component managing the gRPC connection:

- Builds mTLS channel using Tonic with `ClientTlsConfig` (CA cert + client identity)
- Uses `tokio::fs::read_to_string` (async) for cert loading — no blocking I/O in async context
- Opens a `stream_events` RPC, returning an `mpsc::Sender<SecurityEvent>`
- Tonic wraps the receiver in `ReceiverStream` — closing the sender signals stream end
- Background task logs the `StreamSummary` response

### 4.4 Ingest Loop

- Consumes events from Collector via bounded `mpsc::Receiver<SecurityEvent>`
- **Channel capacity:** configurable via `AGENT_QUEUE_CAPACITY` env var (default: 10,000)
- **Drop policy:** when channel is full, the Collector call to `tx.send().await` will
  **back-pressure** (Tokio bounded channel blocks the sender). Collector's `interval`-based
  loop naturally throttles. If blocking is unacceptable, use `try_send` and log dropped events.
  The default implementation uses blocking `send` (back-pressure preferred over silent drops).
- Batches up to `BATCH_SIZE` events (default 500) or flushes every `FLUSH_INTERVAL_MS` (default 1000ms)
- On stream closure or error: reconnects with exponential backoff (1s → 60s cap, jitter recommended)
- Buffers accumulated during reconnection are held in the bounded mpsc channel; once at capacity,
  Collector back-pressures.

### 4.5 Collector

- Simulated OS event generator (100ms tick = ~10 events/s) as placeholder
- Upgrade path: replace with eBPF probes or `/proc` polling without changing `client.rs` interface

## 5. Component: sentinelops-control (Java 21)

### 5.1 Virtual Threads

```java
@Bean
public GrpcServerConfigurer virtualThreadExecutor() {
    return sb -> sb.executor(Executors.newVirtualThreadPerTaskExecutor());
}
```

Each gRPC call gets a dedicated Virtual Thread. Blocking I/O (DB, Kafka) does not consume
OS threads — scales to tens of thousands of concurrent agents.

`application.yml` must include `spring.threads.virtual.enabled=true` (Spring Boot 3.2+).

### 5.2 AgentIdentityInterceptor (Zero Trust)

Global gRPC server interceptor that:
1. Extracts `SSLSession` from gRPC transport attributes
2. Parses `CN` from the `X500Principal` of the peer X.509 certificate
3. **Normalises to lowercase** before storing: `cn.toLowerCase()` — RFC 5280 CNs are
   case-insensitive but Java's `X500Principal.getName()` returns the literal string from
   the cert; mismatched case would cause legitimate agents to be rejected
4. Stores CN in `Context.Key<String> CERT_CN` for downstream access
5. Rejects calls with no client cert with `Status.UNAUTHENTICATED`

**Zero Trust invariant:** both `AGENT_ID` env var (Rust side) and cert `CN` (Java side)
MUST be lowercase UUID v4 strings. Enforced at provisioning time by `gen-dev-certs.sh`
and at runtime by the interceptor's `toLowerCase()` normalisation.

### 5.3 IngestionServiceImpl

- `sendEvent` (unary): validates `agent_id.toLowerCase() == certCN`; returns `EventResponse`
- `streamEvents` (streaming): returns `StreamObserver<SecurityEvent>` that:
  - On `onNext`: validates `agent_id.toLowerCase() == certCN`; increments accepted/rejected counters
  - On `onCompleted`: returns `StreamSummary` with session stats
  - On `onError`: logs error with session ID for audit
- Future: `onNext` publishes to Kafka topic or persists to PostgreSQL

### 5.4 mTLS Configuration (application.yml)

```yaml
spring:
  threads:
    virtual:
      enabled: true    # Required for Virtual Threads (Spring Boot ≥ 3.2)

grpc:
  server:
    port: 9090
    security:
      enabled: true
      certificate-chain: classpath:certs/server.pem
      private-key: classpath:certs/server.key
      trust-certificate-collection: classpath:certs/ca.pem
      client-auth: REQUIRE   # enforce mTLS — no client cert = rejection
```

## 6. Security: Dev PKI (`scripts/gen-dev-certs.sh`)

### 6.1 Certificate structure

```
SentinelOps Dev CA (ca.pem / ca.key)
        │
   ┌────┴────────────────┐
   │                     │
server.pem           agent.pem
CN=sentinelops-      CN=agent-uuid-1234 (lowercase UUID)
control.internal     (= AGENT_ID env var, lowercase)
   │                     │
Java Control         Rust Agent
```

### 6.2 Zero Trust invariant

`AGENT_ID` (env var, lowercase UUID v4) **must equal** `CN` in `agent.pem` (also lowercase).
They are provisioned together at bootstrap. Divergence = spoofing attempt → stream rejected
with `PERMISSION_DENIED`.

### 6.3 Script behaviour

1. Generates 4096-bit CA (10-year validity)
2. Generates 2048-bit server cert with SAN (`DNS:sentinelops-control.internal`, `DNS:localhost`, `IP:127.0.0.1`)
3. Generates 2048-bit agent cert with `CN=${AGENT_UUID}` (lowercase enforced in script)
4. Verifies chain with `openssl verify`
5. Cleans intermediate artifacts (CSRs, serials)

### 6.4 Staging / production SAN guidance

The server cert SAN must include **every DNS name or IP address** that agents use to
connect. Before any multi-host deployment:

- Add the actual hostname(s) to `server-ext.cnf` in the `subjectAltName` line
- Example: `DNS:sentinel-control.prod.internal,IP:10.10.0.5`
- Agents that connect to a hostname not in the SAN will fail TLS hostname verification
  with a non-retryable error — this is not a backoff scenario, it requires cert regeneration

In production, use HashiCorp Vault PKI Engine or AWS Private CA with short-TTL certs
(24h) and automatic rotation via cert-manager or Vault agent sidecar.

### 6.5 Gitignore entries

```gitignore
# mTLS dev certs — private keys MUST NOT be committed
certs/*.key
certs/*.srl
```

## 7. Data Flow

### Hybrid mode (parallel paths)

```
[OS Events]
    │
    ▼ 100ms tick (simulated) / eBPF (future)
[Collector]
    │
    ├──── mpsc copy A ────▶ [StreamingSession (Tonic/mTLS)]
    │                              │ HTTP/2 stream
    │                              │ agent_id=agent-uuid-1234
    │                              │ cert CN=agent-uuid-1234
    │                              ▼
    │                    [AgentIdentityInterceptor]
    │                      extract + normalise CN
    │                              │
    │                              ▼
    │                    [IngestionServiceImpl.streamEvents()]
    │                      validate: agent_id == CN ✓
    │                      → TODO: Kafka / PostgreSQL
    │                              │ (stream closed)
    │                              ▼
    │                    [StreamSummary { accepted, rejected, sessionId }]
    │
    └──── mpsc copy B ────▶ [sentinelops-rust Aggregator] (parallel, local)
                                L1 detection (DashMap)
                                ML feature extraction
                                Batch ingest → PostgreSQL
```

### Subordinate mode

Only path A runs. sentinelops-rust is not started.

### Autonomous mode

Only path B runs (sentinelops-rust standalone). sentinelops-agent is not deployed.

## 8. Error Handling & Resilience

| Failure | Rust Agent behavior | Java Control Plane behavior |
|---------|--------------------|-----------------------------|
| mTLS handshake fail | Log + backoff reconnect (1s→60s, jitter) | Reject at transport layer |
| agent_id mismatch | N/A (field is local) | Log warning, increment `rejected_count` |
| Network partition | Back-pressure Collector via bounded channel; reconnect on next flush | gRPC deadline exceeded, client reconnects |
| Java restart | Agent reconnects on next flush tick | New session ID, no state lost |
| Stream error | `onError` logged, outer loop reconnects | Session stats logged and discarded |
| Agent queue full | Collector blocks (`send().await`) — back-pressure preferred over drop | N/A |

## 9. Testing Strategy

- **sentinelops-agent**: unit tests for `AgentConfig::from_env`, mock `SecurityEvent` dispatch
- **Collector**: test event shape and rate (100ms tick assertions)
- **StreamingSession integration**: in-process Tonic server using plaintext channel
  (`Channel::from_static("http://...")` without `tls_config`) for unit tests; a separate
  integration test with real certs validates mTLS end-to-end
- **Java IngestionServiceImpl**: `@SpringBootTest` with `GrpcServerExtension`
  (`io.grpc.testing.GrpcServerExtension`), mock interceptor context via
  `Context.current().withValue(CERT_CN, "test-agent-uuid")`
- **AgentIdentityInterceptor**: unit test with mock `SSLSession` returning known CN,
  verify `toLowerCase()` normalisation handles mixed-case input
- **E2E**: `docker-compose` with real certs from `gen-dev-certs.sh`,
  Rust agent → Java server, verify `StreamSummary`
