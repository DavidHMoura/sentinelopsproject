# SentinelOps Dual-Stack Architecture Design

**Date:** 2026-03-16
**Status:** Approved
**Author:** Collaborative design session

---

## Overview

SentinelOps evolves from a single Rust service into a dual-stack platform with:

1. **sentinelops-agent** (new Rust crate) — OS-level event capture, gRPC client
2. **sentinelops-rust** (existing, evolved) — Aggregator/Edge Node, L1 detection, ML features
3. **sentinelops-control** (new Java 21) — Control Plane orchestrator, high throughput

Communication between Rust and Java uses **gRPC over mTLS** (Zero Trust).

## 2. Protocol: gRPC over mTLS

**Choice rationale:**
- gRPC runs over HTTP/2: connection multiplexing, single TCP connection for thousands of events
- Protobuf: binary serialization, ~5–10× smaller payload than JSON, no UTF-8 validation overhead
- Client-side streaming: agent dispatches N events without waiting for per-event ACK
- mTLS: mutual certificate authentication — passwords/API keys can leak; certificates have lifecycle control

**Why not REST:** JSON serialization CPU overhead is prohibitive at millisecond-level telemetry rates.

## 3. Protobuf Contract — `proto/sentinel.proto`

```protobuf
syntax = "proto3";

package sentinel;

option java_multiple_files  = true;
option java_package         = "com.sentinelops.grpc";
option java_outer_classname = "SentinelProto";

service IngestionService {
  // Unary: single event, used for debug / critical events needing individual ACK
  rpc SendEvent (SecurityEvent) returns (EventResponse);

  // Client-side streaming: production mode
  // Agent opens ONE HTTP/2 stream, pushes N events, server responds once with StreamSummary
  rpc StreamEvents (stream SecurityEvent) returns (StreamSummary);
}

message SecurityEvent {
  string event_id     = 1;  // UUID v4, generated by agent
  string timestamp    = 2;  // RFC 3339 UTC
  string event_type   = 3;  // e.g. "os.process.exec", "net.conn.outbound"
  string source_ip    = 4;  // origin IP of the event (not the agent IP)
  bytes  meta_payload = 5;  // compressed JSON or MessagePack — no UTF-8 overhead

  // Zero Trust identity — validated server-side against mTLS cert CN/SAN
  string agent_id     = 6;  // UUID of agent, must match CN in mTLS client cert
  string source_host  = 7;  // FQDN or hostname of host OS
}

message EventResponse {
  bool   accepted = 1;
  string message  = 2;
  string event_id = 3;  // echo of event_id for client-side correlation
}

message StreamSummary {
  uint32 accepted_count = 1;
  uint32 rejected_count = 2;
  string session_id     = 3;  // gRPC session ID for audit trail
}
```

**Key design decisions:**
- `bytes meta_payload` not `string`: avoids Protobuf UTF-8 validation CPU cost; accepts zstd/LZ4 compressed JSON or MessagePack
- `StreamSummary` separate from `EventResponse`: streaming returns aggregate stats, not per-event struct
- `agent_id` must match cert CN: enforces Zero Trust at payload level, not just transport layer
- RFC 3339 `string` timestamp: avoids `google.protobuf.Timestamp` dependency; upgrade path available

## 4. Component: sentinelops-agent (Rust)

### 4.1 AgentMode

Configured via `AGENT_MODE` env var:

| Mode | Behavior |
|------|----------|
| `autonomous` | No gRPC; local detection only (existing sentinelops-rust handles all) |
| `subordinate` | All events forwarded to Control Plane; minimal local processing |
| `hybrid` | L1 local detection (sentinelops-rust) + replicate to Control Plane |

### 4.2 StreamingSession

Core component managing the gRPC connection:

- Builds mTLS channel using Tonic with `ClientTlsConfig` (CA cert + client identity)
- Opens a `stream_events` RPC, returning an `mpsc::Sender<SecurityEvent>`
- Tonic wraps the receiver in `ReceiverStream` — closing the sender signals stream end
- Background task logs the `StreamSummary` response

### 4.3 Ingest Loop

- Consumes events from Collector via `mpsc::Receiver<SecurityEvent>`
- Batches up to `BATCH_SIZE` events (default 500) or flushes every `FLUSH_INTERVAL_MS` (default 1000ms)
- On stream closure or error: reconnects with exponential backoff (1s → 60s cap)
- Uses `tokio::fs::read_to_string` (async) for cert loading — no blocking I/O in async context

### 4.4 Collector

- Simulated OS event generator (100ms tick = ~10 events/s) as placeholder
- Upgrade path: replace with eBPF probes or `/proc` polling without changing `client.rs` interface

## 5. Component: sentinelops-control (Java 21)

### 5.1 Virtual Threads

```java
@Bean
public GrpcServerConfigurer virtualThreadExecutor() {
    return sb -> sb.executor(Executors.newVirtualThreadPerTaskExecutor());
}
```

Each gRPC call gets a dedicated Virtual Thread. Blocking I/O (DB, Kafka) does not consume OS threads — scales to tens of thousands of concurrent agents.

### 5.2 AgentIdentityInterceptor (Zero Trust)

Global gRPC server interceptor that:
1. Extracts `SSLSession` from gRPC transport attributes
2. Parses `CN` from the `X500Principal` of the peer X.509 certificate
3. Stores CN in `Context.Key<String> CERT_CN` for downstream access
4. Rejects calls with no client cert with `Status.UNAUTHENTICATED`

### 5.3 IngestionServiceImpl

- `sendEvent` (unary): validates `agent_id == certCN`; returns `EventResponse`
- `streamEvents` (streaming): returns `StreamObserver<SecurityEvent>` that:
  - On `onNext`: validates `agent_id == certCN`; increments accepted/rejected counters
  - On `onCompleted`: returns `StreamSummary` with session stats
  - On `onError`: logs error with session ID for audit
- Future: `onNext` publishes to Kafka topic or persists to PostgreSQL

### 5.4 mTLS Configuration (application.yml)

```yaml
grpc:
  server:
    port: 9090
    security:
      enabled: true
      certificate-chain: classpath:certs/server.pem
      private-key: classpath:certs/server.key
      trust-certificate-collection: classpath:certs/ca.pem
      client-auth: REQUIRE
```

## 6. Security: Dev PKI (`scripts/gen-dev-certs.sh`)

### Certificate Structure

```
SentinelOps Dev CA (ca.pem / ca.key)
        │
   ┌────┴────────────────┐
   │                     │
server.pem           agent.pem
CN=sentinelops-      CN=agent-uuid-1234
control.internal     (= AGENT_ID env var)
   │                     │
Java Control         Rust Agent
```

### Zero Trust Invariant

`AGENT_ID` (env var) **must equal** `CN` in `agent.pem`. They are provisioned together at bootstrap. Divergence = spoofing attempt → stream rejected with `PERMISSION_DENIED`.

### Script behavior

1. Generates 4096-bit CA (10-year validity)
2. Generates 2048-bit server cert with SAN (`DNS:localhost`, `IP:127.0.0.1`)
3. Generates 2048-bit agent cert with `CN=${AGENT_UUID}`
4. Verifies chain with `openssl verify`
5. Cleans intermediate artifacts (CSRs, serials)

### Production guidance

- Use HashiCorp Vault PKI Engine or AWS Private CA
- Short TTL certs (24h) with automatic rotation via cert-manager or Vault agent sidecar
- Never store `.key` files in version control

## 7. Data Flow (Production Session)

```
[OS Events]
    │
    ▼ 100ms tick (simulated) / eBPF (future)
[Collector] ──mpsc──▶ [StreamingSession (Tonic)]
                            │ HTTP/2 stream (mTLS)
                            │ agent_id=agent-uuid-1234
                            │ cert CN=agent-uuid-1234
                            ▼
                  [AgentIdentityInterceptor]
                    extract CN from X.509
                    store in gRPC Context
                            │
                            ▼
                  [IngestionServiceImpl.streamEvents()]
                    validate: agent_id == CN  ✓
                    → accepted++
                    → TODO: publish Kafka / persist PostgreSQL
                            │ (stream closed)
                            ▼
                  [StreamSummary { accepted, rejected, sessionId }]
                            │
                            ▼ (hybrid/autonomous mode)
                  [sentinelops-rust Aggregator]
                    L1 detection (DashMap)
                    ML feature extraction
                    Batch ingest → PostgreSQL
```

## 8. Error Handling & Resilience

| Failure | Rust Agent behavior | Java Control Plane behavior |
|---------|--------------------|-----------------------------|
| mTLS handshake fail | Log + backoff reconnect (1s→60s) | Reject at transport layer |
| agent_id mismatch | N/A (field is local) | Log warning, increment `rejected_count` |
| Network partition | Backoff reconnect, buffer in mpsc channel | gRPC deadline exceeded, client reconnects |
| Java restart | Agent reconnects on next flush tick | New session ID, no state lost |
| Stream error | `onError` logged, outer loop reconnects | Session stats logged and discarded |

## 9. Testing Strategy

- **sentinelops-agent**: unit tests for `AgentConfig::from_env`, mock `SecurityEvent` dispatch
- **Collector**: test event shape and rate (100ms tick assertions)
- **StreamingSession**: integration test with in-process Tonic server (no real mTLS in unit tests)
- **Java IngestionServiceImpl**: `@SpringBootTest` with `GrpcServerExtension`, mock interceptor context
- **AgentIdentityInterceptor**: unit test with mock `SSLSession` returning known CN
- **E2E**: `docker-compose` with real certs, Rust agent → Java server, verify `StreamSummary`
